# Отчёт агента человеку

Тексты, которыми агент сообщает о своей работе: итог задачи, статус долгой работы, сводка по расписанию, уведомление о завершении, handoff-резюме для другого исполнителя, сообщение о блокере, отчёт об инциденте. Это самый частый русский текст в работе агента, и читают его чаще всего с телефона. Сначала загрузи `russian-text-craft`. Правила окружения о доставке, обращении и формате сообщений имеют приоритет.

## Когда применять

- Финальный ответ после содержательной задачи; сводка или дайджест по расписанию; статус каждые N минут; резюме при завершении задачи на доске; сообщение «нужно решение»; отчёт о сбое.
- Не применять: аналитическая записка по чужим материалам (`ru-analytical-note`), документация (`ru-technical-docs`), письмо третьему лицу (`ru-business-correspondence`), короткий ответ на простой вопрос.

## Главный принцип

Первое предложение отвечает на вопрос «получилось или нет и нужно ли от меня что-то». Если часть нужных проверок не выполнена, это видно уже в нём: «nginx обновлён, сайт отвечает; две проверки не выполнены». Всё остальное — для тех, кто хочет проверить.

## Структура

1. **Итог.** Сделано / сделано частично / не сделано / нужно решение — и главный результат в одной-двух фразах. С адресом, если он есть: ссылка, путь к файлу, название.
2. **Что изменилось.** Где и что именно: сервис, файл, настройка, документ. Только существенное.
3. **Как проверено.** Чем подтверждено и что именно показала проверка, человеческими словами: «открыл файл и просмотрел все страницы», «сверил каждый файл в репозитории с локальной копией». Не «verified», не «PASS». У каждой нужной проверки — состояние по ядру: пройдена, найдено несоответствие, не проверено, неприменимо. Тайм-аут, отказ в доступе, упавший инструмент — «не проверено» с причиной, а не успех.
4. **Что не проверено и ограничения.** Честно и отдельно от успехов.
5. **Что нужно от читателя.** Решение — с вариантами и рекомендацией; действие — с точной командой или шагом. Если ничего не нужно, раздел опускается.

Для **статуса долгой работы**: что сделано с прошлого сообщения → что сейчас идёт → когда следующий шаг → есть ли риск. Без повторения всего контекста.

Для **сводки по данным** (почта, календарь, радар): сначала то, что требует действия, с абсолютными датами; затем справочное; одинаковое не повторяется; источник каждого пункта понятен.

Для **handoff-резюме другому исполнителю**: одна-три фразы для человека + машинные поля отдельно (идентификаторы, хеши, пути, команды тестов). В человеческой части нет внутреннего жаргона.

Для **блокера**: что именно мешает, что уже попробовано, какое решение нужно и какие есть варианты.

## Язык

- Простые слова; термин поясняется при первом появлении одной фразой и с практическим следствием («кэш — копия ответа, поэтому изменения увидите через пять минут»).
- Без смеси языков и внутреннего жаргона: «blob SHA совпадают» → «каждый файл на GitHub совпадает с проверенной копией»; «fresh clone» → «чистая копия репозитория».
- Идентификаторы, пути и хеши — только если читатель будет ими пользоваться; иначе в машинную часть.
- Цифры с единицами, даты абсолютные («в среду, 12 ноября»), время с часовым поясом, если он неочевиден.
- Не обещать непроверенное: «должно работать» — это «не проверял». «Всё проверено» — только если не осталось ни одной невыполненной нужной проверки.
- Без «Отлично!», «Готово! 🎉», без перечисления всех выполненных команд, без самохвальбы («тщательно», «всесторонне»).
- Длина по умолчанию — то, что читается с телефона за минуту: до ~1200 знаков. Подробности — во вложении или по запросу.
- Жирный — только для итога и действия от читателя. Списки — когда пунктов действительно несколько.

## Нейроследы жанра

- Начало с хода работы («Сначала я загрузил навык…») вместо итога.
- «Всё готово, всё проверено» без указания, что и как проверено.
- Внутренние идентификаторы и английские термины в каждой строке.
- Длинный список мелких выполненных шагов, в котором тонет единственное нужное решение.
- Успех и ограничения вперемешку, ограничения в последней строке мелким текстом.
- «Если нужно, могу ещё…» с тремя предложениями услуг в конце.

## Процедура

1. Сформулируй итог одной фразой: статус + главный результат. Готово: фразу можно отправить отдельно.
2. Отбери существенные изменения и проверки; остальное — в машинную часть или вложение. Готово: нет пункта, который читателю не нужен.
3. Раздели проверенное и непроверенное. Готово: ограничения отдельным пунктом.
4. Сформулируй, что нужно от читателя, или убери раздел. Готово: решение с вариантами или явное «ничего не нужно».
5. Переведи жаргон на русский, проверь абсолютность дат и наличие адресов результатов. Готово: нет непоясненного термина.
6. Самопроверка по ядру со `--genre technical` или `general`; для сообщения в чат — с `--chat`: обращение по правилам окружения не блокирует, плейсхолдеры и технические следы — блокируют. Готово: нет плейсхолдеров, непроверенное названо непроверенным.

## Ловушки

- Отчёт не доказательство: в нём упоминается только то, что действительно проверено в этой работе.
- Сводки по расписанию не должны пересказывать прошлую сводку, если ничего не изменилось.
- Обращение и форма приветствия определяются правилами окружения, а не этим навыком. В документ для третьих лиц такое обращение не переносится.
- Сбой проверки — не успех: «проверка сертификата прервана по тайм-ауту» пишется так и стоит рядом с итогом, а не теряется в конце.

## Проверка результата

Готово, когда: первая фраза — итог со статусом, включая невыполненные проверки; изменения названы с адресами; проверка описана человеческими словами; ограничения отдельно; нужное решение сформулировано с вариантами; объём читается с телефона; жаргон пояснён или убран в машинную часть.
