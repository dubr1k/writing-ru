## Границы применения

Текущее задание, требования издания и ограничения безопасности имеют приоритет над стилевыми советами. «Нейроследы» ниже — историческое название редакторских сигналов, не способ установить авторство или ИИ-генерацию. Нулевые находки не гарантируют качество.

Внешние навыки (`grounded-citations`, `docx`, `mdtoword`, `xlsx`, `powerpoint`, `office-document-quality`, `obsidian`, `llm-wiki`, `email-inbox-triage`) не входят в набор и необязательны. Используй их только если они установлены; иначе проверь источники доступными средствами, согласуй формат и не выдумывай команды интеграций. Word не является обязательным форматом.

# Грантовая заявка и научно-проектный текст

Разделы заявок в научные фонды (РНФ, РФФИ-преемники, университетские конкурсы), программы НИР, концепции проектов, обоснования тем, описания ожидаемых результатов. Отличие от статьи: текст должен убедить эксперта, что проект нужен, выполним этими людьми в этот срок и даст проверяемый результат. Сначала загрузи `russian-text-craft`; для сравнения с существующими решениями — `grounded-citations`.

## Когда применять

- Написать или переработать разделы заявки: проблема, актуальность, новизна, цели и задачи, подход и методы, план работ, ожидаемые результаты, задел коллектива.
- Свести разрозненные черновики разных авторов в одну связную заявку.
- Проверить заявку на связность, достижимость, соответствие требованиям фонда.
- Не применять: статья по результатам проекта (`ru-academic-article`), отчёт по гранту (ближе к `ru-analytical-note` с требованиями фонда), рецензия на чужую заявку (`ru-review-and-feedback`).

## Что выяснить до письма

1. Конкурс и форма: точное название, требования к разделам, лимиты знаков по каждому, критерии экспертизы (обычно опубликованы), срок. Эксперт читает по критериям — текст строится по ним.
2. Какие черновики уже есть, какой из них новее, кто автор какого раздела. Разночтения (название проекта, аббревиатуры, нумерация) зафиксируй списком до правки.
3. Задел: что коллектив уже сделал по теме — публикации, прототипы, данные. Без задела «новизна» не убеждает.
4. Что обещается как результат: статья, прототип, методика, база данных, рекомендации. У каждого — измеримая форма.
Готово, когда есть требования конкурса, карта черновиков с датами и список обещаемых результатов.

## Сквозная логика заявки

Эксперт ищет одну цепочку и проверяет каждое звено:

**Проблема** (что не работает или неизвестно, с доказательством) → **почему это важно решить сейчас** (не «актуально», а кому и чем это мешает) → **что уже сделано другими и чего не хватает** (сравнение, а не заявление о новизне) → **наш подход** (что именно мы делаем иначе) → **задачи** (шаги, каждый с результатом) → **методы** (как решаем каждую задачу) → **результаты** (что получим, в какой форме, как проверить) → **коллектив и задел** (почему мы это сможем) → **план и ресурсы**.

Правило связности: каждая задача выводится из проблемы, каждый метод привязан к задаче, каждый результат привязан к задаче. Задача без результата, результат без задачи, метод без задачи — дефект, который эксперт заметит первым.

## Язык заявки

- Конкретность вместо масштаба. «Разработать методику оценки X для Y на выборке Z» лучше «комплексного подхода к проблеме X».
- Новизна доказывается сравнением: «в отличие от [работа 1], где …, и [работа 2], где …, мы …». Фразы «не имеет аналогов», «впервые в мировой практике», «ни в академической литературе, ни в индустрии» без сравнительного обзора — риск для заявки, а не аргумент.
- Достижимость важнее амбиции. Эксперт охотнее верит проекту, который обещает проверяемый результат, чем «прорыву». Если замысел амбициозен, разбей его на этап с гарантированным результатом и этап с исследовательским риском, и назови риск.
- Один словарь на всю заявку: название проекта, аббревиатуры, названия компонентов и этапов совпадают во всех разделах. Составь глоссарий в рабочем файле.
- Нормативные ссылки (указы, стратегии, стандарты) — с проверкой реквизитов и актуальной редакции; не цитируй по памяти.
- Канцелярит допустим в минимальной дозе, которой требует форма («в рамках проекта предполагается» — один раз, не в каждом абзаце). Глаголы действия: «измерим», «соберём», «сравним», «опубликуем».
- Без жирного и списков там, где форма требует связного текста; списки — в задачах и результатах, если форма их допускает.

## Нейроследы, характерные для жанра

- «Актуальность темы обусловлена» + абзац общих слов о цифровизации.
- Новизна как набор прилагательных: «инновационный», «уникальный», «комплексный», «междисциплинарный».
- Задачи-глаголы без объекта и результата: «изучить», «проанализировать», «разработать» без «что получим».
- Результаты как пожелания: «повышение качества», «формирование компетенций» — без измеримой формы.
- Несколько равноправных направлений без приоритета (система + бенчмарк + генератор + методика) — эксперт не поймёт, что главное.
- Опечатки и разнобой терминов между разделами — признак сборки из кусков.

## Процедура

1. Прочитай все черновики целиком; составь таблицу: файл → разделы → дата/версия → расхождения. Готово: таблица есть, расхождения перечислены.
2. Выпиши требования и критерии конкурса; построй скелет заявки по ним с лимитами. Готово: скелет с лимитами.
3. Сформулируй проблему, главный результат и одно главное отличие от существующих решений — по одному предложению. Готово: три предложения без штампов, с которыми можно спорить.
4. Проверь сравнительную часть по источникам (`grounded-citations`). Готово: у каждого «в отличие от» есть ссылка.
5. Напиши разделы по скелету, сверяя цепочку связности. Готово: таблица «задача → метод → результат» заполнена без пустых клеток.
6. Унифицируй словарь, проверь реквизиты нормативных документов, исправь опечатки. Готово: глоссарий применён, реквизиты проверены.
7. Самопроверка по `russian-text-craft`; жанровая: достижимость каждого результата, отсутствие голословной новизны. Готово: чеклист пройден.
8. Оформи по форме фонда (часто — Word с жёсткими полями); сообщи пользователю, что требует его решения: приоритет направлений, состав коллектива, биографии, сроки.

## Ловушки

- Не выбирай приоритет направлений за автора: предложи варианты и последствия каждого.
- Биографии участников и сведения о заделе — только из проверяемых источников или от пользователя; не дописывай регалии.
- «Дальше не правил» и подобные пометки в черновике — сигнал незавершённости раздела, не текст для переноса.
- Таблицы бенчмарков, стандартов, инструментов проверяй построчно: описания из черновиков бывают ошибочными.

## Проверка результата

Готово, когда: разделы соответствуют форме и лимитам; цепочка проблема → задачи → методы → результаты замкнута; каждое утверждение о новизне подкреплено сравнением со ссылкой; словарь единый; скрипт `ru_text_check.py` прогнан; пользователю передан список решений, которые остаются за ним.
