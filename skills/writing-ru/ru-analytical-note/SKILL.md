## Границы применения

Текущее задание, требования издания и ограничения безопасности имеют приоритет над стилевыми советами. «Нейроследы» ниже — историческое название редакторских сигналов, не способ установить авторство или ИИ-генерацию. Нулевые находки не гарантируют качество.

Внешние навыки (`grounded-citations`, `docx`, `mdtoword`, `xlsx`, `powerpoint`, `office-document-quality`, `obsidian`, `llm-wiki`, `email-inbox-triage`) не входят в набор и необязательны. Используй их только если они установлены; иначе проверь источники доступными средствами, согласуй формат и не выдумывай команды интеграций. Word не является обязательным форматом.

# Аналитическая записка, обзор, отчёт

Тексты, которые превращают собранные факты в оценку и решение: аналитическая записка «что это и что делать», сравнительный обзор технологий или продуктов, критический разбор проекта, анализ конкурентов, отчёт с выводами и ограничениями. Сначала загрузи `russian-text-craft`; для источников — `grounded-citations`.

## Когда применять

- «Разбери документы и скажи, что с этим делать», «сравни X и Y», «критически оцени проект», «проанализируй конкурентов», «напиши отчёт с выводами».
- Отчёт по задаче с данными, где нужны текст, выводы и ограничения (таблицы — в Excel через `xlsx`, если пользователь так решил).
- Не применять: заметка для себя в базу знаний (`ru-knowledge-note`), рецензия на чужой текст (`ru-review-and-feedback`), публицистика с позицией для внешнего читателя (`ru-expert-commentary`).

## Что выяснить до письма

1. Кто читает и какое решение принимает по итогам. Записка для руководителя и обзор для коллеги-разработчика — разные тексты.
2. Вопрос, на который отвечает записка, одним предложением. Если вопросов несколько — порядок приоритета.
3. Какие данные есть, какие нужны, но отсутствуют. Отсутствующие — отдельный раздел, а не умолчание.
4. Формат: Word, Markdown, Excel для таблиц; объём; нужны ли рекомендации или только оценка.
Готово, когда вопрос сформулирован и известно, кто и что решит по тексту.

## Структура

Записка читается сверху вниз с убывающей обязательностью: первое — то, без чего нельзя; последнее — для тех, кто хочет подробностей.

1. **Ответ сразу.** Первый абзац — главный вывод и его основание в двух-четырёх предложениях. Читатель, который остановится здесь, уже знает ответ.
2. **Что это такое** (если предмет незнаком читателю): простыми словами, без истории вопроса.
3. **Разбор.** По аспектам, каждый аспект — факт, затем оценка, затем следствие. Внутри аспекта: что видно в материалах (со ссылкой на документ/страницу/источник), что это означает, чем рискует читатель.
4. **Сравнение** (для обзоров): критерии выбраны до сравнения и названы; таблица уместна здесь и только здесь; после таблицы — текст о том, что из неё следует.
5. **Что не готово / что неизвестно.** Пробелы в данных, непроверенные утверждения, допущения расчётов.
6. **Что делать.** Варианты с последствиями, а не одна «рекомендация». Если решение за читателем — так и напиши и назови, что требует его решения.

Заголовки разделов — содержательные («Новизна заявлена, но не доказана»), не рубрикаторные («Анализ», «Выводы»).

## Язык записки

- Оценка — явная и обоснованная: «это утверждение авторов, а не установленный факт; сравнительного обзора в разделе нет». Записка без оценки — пересказ.
- Факт и интерпретация разделены словами: «в документе написано», «я читаю это как», «моя интерпретация», «это следует проверить».
- Цифры с источником и единицами; расчёты с допущениями в явном виде. Диапазон честнее точки, если данных мало.
- Детальность достигается конкретикой, а не объёмом общих слов. Длинный раздел должен быть длинным из-за фактов.
- Допустимо «я бы» и «на мой взгляд» в рекомендациях — читатель должен видеть, где кончается анализ и начинается совет.
- Таблица — для сопоставления по одинаковым критериям; не для текста, который можно сказать абзацем. В Word по умолчанию таблицы минимальны; сводные таблицы — в Excel, если так договорились.
- Без «рекомендуется рассмотреть возможность», «целесообразно», «представляется необходимым». Прямо: «советую», «стоит», «не стоит», «нужно решить».

## Нейроследы, характерные для жанра

- Раздел «Сильные стороны / слабые стороны / возможности / угрозы» без приоритета, где всё равноценно.
- «Рекомендации» в виде списка глаголов без условий и последствий («усилить», «оптимизировать», «рассмотреть»).
- Пересказ документа по разделам вместо ответа на вопрос.
- Таблица со столбцами «Критерий / Описание / Оценка» и оценками «высокая/средняя/низкая» без расшифровки.
- Введение об «актуальности» вместо ответа.
- Одинаковые по длине разделы, каждый с мини-выводом.

## Процедура

1. Прочитай все материалы целиком (документы, сайты, данные); веди журнал фактов с локаторами (файл/страница/URL). Готово: журнал есть, каждый факт с локатором.
2. Сформулируй главный вывод одним абзацем. Если не получается — материалов недостаточно; зафиксируй пробелы и либо добери, либо напиши записку о пробелах.
3. Выбери аспекты разбора и критерии сравнения; запиши их до того, как писать оценки. Готово: список критериев.
4. Напиши разбор по структуре; каждому выводу — основание из журнала. Готово: нет вывода без факта.
5. Напиши «что неизвестно» и «что делать» с вариантами. Готово: у каждого варианта названо последствие.
6. Самопроверка по `russian-text-craft`; жанровая: ответ в первом абзаце; оценка отделена от факта; нет «рекомендуется рассмотреть». Готово: чеклист пройден.
7. Оформи (Word — если запрошен, по согласованным требованиям; таблицы — как договорились), открой файл после записи, сообщи, что проверено и что нет.

## Ловушки

- Не смягчай вывод ради вежливости к авторам документа: записка для читателя, а не для них. Вежливость — в форме, не в содержании.
- Не придумывай данные для «полноты сравнения»: пустая клетка таблицы с пометкой «нет данных» честнее.
- Детальный разбор не означает длинный пересказ: каждый абзац должен добавлять факт или оценку.
- Если пользователь спрашивает «что это и что мне делать», ответ на второе важнее первого.

## Проверка результата

Готово, когда: главный вывод стоит первым; каждый факт с локатором; оценка и факт различены; пробелы данных названы отдельным разделом; варианты действий с последствиями; скрипт `ru_text_check.py` прогнан; файл открыт после записи.
