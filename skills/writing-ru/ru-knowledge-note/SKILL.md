## Границы применения

Текущее задание, требования издания и ограничения безопасности имеют приоритет над стилевыми советами. «Нейроследы» ниже — историческое название редакторских сигналов, не способ установить авторство или ИИ-генерацию. Нулевые находки не гарантируют качество.

Внешние навыки (`grounded-citations`, `docx`, `mdtoword`, `xlsx`, `powerpoint`, `office-document-quality`, `obsidian`, `llm-wiki`, `email-inbox-triage`) не входят в набор и необязательны. Используй их только если они установлены; иначе проверь источники доступными средствами, согласуй формат и не выдумывай команды интеграций. Word не является обязательным форматом.

# Заметка для базы знаний

Тексты, которые пользователь пишет для себя и к которым вернётся: исследовательские и технические заметки в Obsidian, сравнение инструментов или моделей, конспект статьи с выводами, перевод с комментарием, подборка материалов с разметкой «что мне с этим делать». Отличие от записки для другого читателя: будущий читатель — сам автор через месяц, он помнит контекст смутно и ищет в заметке ответ быстро. Сначала загрузи `russian-text-craft`; при наличии интеграции можно использовать `obsidian` для выбора папки и шаблона; для источников — `grounded-citations`.

## Когда применять

- «Напиши заметку в мой обсидиан», «сохрани с выводами», «сравни и положи в базу», «законспектируй с переводом», «изучи и запиши, что это значит для курса/проекта».
- Переработать результат исследования в сессии в заметку для вечного хранения.
- Не применять: сохранение статьи целиком без переработки (это процедура вырезки из `obsidian`, не этот навык), записка для внешнего читателя (`ru-analytical-note`), черновик поста (`ru-telegram-post`, хотя сохраняется тоже в Obsidian).

## Что выяснить до письма

1. Папка и соседи: по карте хранилища из `obsidian` найди раздел и прочитай одну-две соседние заметки — их структуру и фронтматтер наследуй.
2. Для какого проекта или вопроса заметка: «применительно к нашему проекту», «для курса X», «просто понять». Заметка без привязки к своему делу реже перечитывается.
3. Источники: что прочитано целиком, что по анонсу, что по чужому пересказу. Это различие пойдёт в заметку.
4. Нужен ли перевод фрагментов и в каком виде (оригинал + перевод, только перевод).
Готово, когда известны папка, соседи и вопрос, на который заметка отвечает.

## Структура заметки

1. **Фронтматтер** по образцу соседей (даты, статус, теги, источники списком, автор как WikiLink). Имя файла без двоеточия и запрещённых символов.
2. **Вывод сверху.** Первый блок после заголовка — два-четыре предложения: что это, что главное, что мне делать. Будущий автор часто дальше не читает.
3. **Факты из источника** — отдельно, с пометкой источника и степени доступа (полный текст / README / блог / анонс). Цифры — как в источнике, с единицами и условиями измерения; расхождения между источниками — названы.
4. **Моя интерпретация** — отдельным блоком, явно: «я читаю это так», «для нас это значит». Не смешивать с фактами.
5. **Что делать / что проверить** — конкретные следующие шаги с привязкой к проекту: «проверить два инструмента на согласованной выборке документов».
6. **Связи** — WikiLinks на соседние заметки и MOC; ссылка в MOC добавляется.
7. **Открытые вопросы** — что не выяснено и почему.

Для сравнения двух версий/инструментов: таблица по критериям, выбранным до сравнения, после таблицы — текст о том, что из неё следует для своего проекта. Для конспекта с переводом: структура оригинала сохраняется; перевод — рядом с оригиналом или вместо него по запросу; собственные ремарки — визуально отделены (цитата или блок «Ремарка»).

## Язык заметки

- Сжато, но полными предложениями: через месяц телеграфный стиль нечитаем.
- Собственные выводы — от первого лица, уверенно: «рекомендую пилот», «не вижу оснований для вердикта о русском OCR».
- Термины и названия — как в источнике, с переводом в скобках при первом появлении, если нужен.
- Степень уверенности помечается словами: «подтверждено бенчмарком», «заявлено в блоге», «моё предположение».
- Без вступлений и без «итогов» — вывод уже наверху.
- Заголовки разделов — короткие и содержательные; структура соседних заметок важнее идеальной.

## Нейроследы, характерные для жанра

- Пересказ источника по порядку без «что мне с этим делать».
- Общие выводы («перспективная технология», «стоит следить») вместо привязки к своему делу.
- Факты и интерпретация в одном абзаце без маркировки.
- Сравнение бенчмарков без оговорок о несопоставимости методик.
- Отсутствие источников и дат (через месяц непонятно, что откуда).
- Дубликат существующей заметки под новым именем.

## Процедура

1. Согласованными средствами хранилища найди папку, проверь дубликаты по названию и URL, прочитай одну-две соседние заметки и шаблон. Готово: папка выбрана, дубликатов нет, образец структуры есть.
2. Прочитай источники; зафиксируй степень доступа к каждому. Готово: список источников с пометками.
3. Напиши вывод (первый блок) до остального; если не пишется — не хватает понимания, дочитай. Готово: вывод в четырёх предложениях с «что делать».
4. Напиши факты, интерпретацию, шаги, вопросы; проставь связи. Готово: факты и интерпретация в разных блоках.
5. Самопроверка по `russian-text-craft`; жанровая: вывод сверху; источники с датами; привязка к проекту; нет дубликата. Готово: чеклист пройден.
6. Сохрани заметку разрешённым для хранилища способом, добавь согласованные ссылки, прочитай заметку обратно. Готово: текст и ссылки соответствуют заданию.
7. Сообщи пользователю путь заметки и главный вывод в двух предложениях.

## Ловушки

- Не меняй хранилище без разрешения. Способ записи и структуру папок согласуй с владельцем.
- Имя файла с двоеточием ломает синхронизацию на macOS/Windows; заменяй на тире.
- Цифры из блога и из README могут расходиться — записывай оба значения с источниками, не усредняй.
- Заметка-пересказ без вывода и привязки — не заметка, а вырезка; если пользователь просил вырезку, делай по процедуре `obsidian`, не по этому навыку.

## Проверка результата

Готово, когда: заметка в нужной папке с фронтматтером по образцу соседей; вывод с «что делать» стоит первым; факты отделены от интерпретации; источники с датами и степенью доступа; ссылка в MOC; заметка прочитана после записи; скрипт `ru_text_check.py` прогнан по тексту заметки.
