## Что сохранено

- Hermes canonical source с его metadata и реальными `skill_view`/`terminal`; это совместимость формата, не live Hermes испытание.
- Все 18 жанров и три исходных reference; дополнен один triage reference. Научные модальности, официальный шаблон, повтор терминов, ритм стенограммы и авторская позиция остаются исключениями, не дефектами по умолчанию.
- Факты и голос различаются: образец голоса не подтверждает биографию, эмоции и мнение для другой темы.
- Python 3.10+ stdlib, прежние CLI flags/JSON поля/exit codes checker. Пороговые эвристики не «обучались» под красивую метрику.
- Никаких новых словесных стоп-списков. Пять адаптаций генерируются, не редактируются как пять независимых копий.

## Доказательства и пределы

Три новых Markdown-сценария сначала упали на исходном checker: длинный indented fence, multibacktick inline и unclosed fence. После исправления все 27 checker tests прошли. Тест цитаты показывает, что ложный красный возможен и в новой версии: triage нужен, не скрыт эвристикой.

Удалён тест длины/пунктуации description и тест извлечения конкретного cp-блока из README: это случайная формулировка/реализация, не пользовательский контракт. Вместо него — реальные install/verify/remove, коллизии, изменённое/чужое дерево, symlink, traversal и whitelist. Privacy проверяется на синтетических canary-файлах; реальные секреты не читаются.

Статическая проверка инструкций не доказывает устойчивость модели к injection. Provider-вызовы и controlled experiment не выполнялись; улучшение качества текста и поведения модели не заявляется. Сценарии triage — примеры для человека/агента, не измеренный бенчмарк.

Markdown parser не является полным CommonMark: сложные container blocks, indented code, reference links и экзотическая вложенная разметка могут остаться в анализе; номера строк сохраняются для поддержанных исключений. DOCX по-прежнему проверяет основной текст, не сноски/вёрстку; недоверенные огромные DOCX не запускайте без внешних ограничений ресурсов.

Ограничения installer, включая конкурентную подмену дерева, описаны до применения в [install.md](install.md). Точные результаты финальных проверок и runtime scope — в [verification.md](verification.md).
