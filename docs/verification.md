## Полная проверка

`python3 -I -m unittest discover -s tests -v`: **44 tests, OK** (10.835 s) на момент портативной поставки; после выпуска 2.2.0 — 52 tests, OK. Внутри этой команды каждый из пяти распакованных пакетов проходит собственные тесты checker и installer. Это не пять live runtime испытаний.

Distribution tests сравнивают все файлы двух независимых сборок побайтно, проверяют SHA256SUMS, 19 навыков/пакет, стандартный frontmatter, относительные ссылки и отсутствие Hermes tool calls. Privacy-canaries вне whitelist не экспортируются; symlink whitelisted файла блокирует чтение. Полный patch применяется через `git apply --check` и `git apply` к копии baseline с `GIT_CEILING_DIRECTORIES`, после чего каждый файл сравнивается с source ZIP. Из source ZIP без `.git` режим `--packages-only` пересобирает пять побайтно одинаковых пакетов.

`python3 -I scripts/build.py`: пять ZIP, source, patch, all-in-one и SHA256SUMS созданы в `dist/`. Результаты повторной сборки проверяются тем же distribution test; финальные hashes — в `dist/SHA256SUMS`, не в исходниках (чтобы не создавать самоссылку).

### Сравнение 2.2.0 и 2.3.0 на модели

42 прогона: семь заданий, две версии, три повтора. Исполнители и оценщики — одна модель (`gpt-6.1-sol`), запущенная субагентами Hermes. Исполнитель получал одну версию навыков под нейтральным именем каталога, читал ядро и один жанровый навык и не знал о сравнении. По журналам ни один исполнитель не открывал чужую копию. Сводные данные: [eval-2.3.0.json](../evidence/eval-2.3.0.json).

| Задание | Что проверяет | 2.2.0 | 2.3.0 |
| --- | --- | --- | --- |
| 1. Корректура точного научного фрагмента | Ловушка: лишние правки | 3 ошибки из 3; лишних правок 0, 0, 0 | 3 из 3; 0, 0, 0 |
| 2. Раздел положения с противоречием сроков | Ловушка: не править числа молча | 2 ошибки из 2; противоречие названо автору 3/3 | 2 из 2; 3/3 |
| 3. Редактура записки с шестью дефектами источников | Целевые дефекты | пропусков 0, вредных правок 0 | пропусков 0, вредных правок 0 |
| 4. Редактура раздела отчёта | Оценки, хвосты, роли; оговорки сохранить | пропусков 0; одна спорная потеря | пропусков 0; одна спорная потеря |
| 5. Markdown к публикации | Технические следы; пример в коде сохранить | параметр ссылки оставлен 3/3 | параметр убран 3/3 |
| 6. Редактура точного фрагмента, «тяжело читается» | Ловушка под давлением | изменено 36, 37, 40 слов; определение со связкой переписано 3/3 | изменено 9, 10, 11 слов; определение сохранено 3/3 |
| 7. Вычитка записки с неверными ссылками | Назвать расхождения, не переписывать | текст не тронут, 5 расхождений названы 3/3 | то же, 3/3 |

Задания 1, 2, 5, 6, 7 оценены скриптом по эталону и ключу. Задания 3 и 4 оценили два независимых оценщика вслепую, по ключу, без пометки версии; их вердикты выборочно перепроверены по текстам.

Что из этого следует:

- Условие «точные тексты не страдают» выполнено: при корректуре обе версии не внесли лишних правок, а при редактуре под давлением новая версия меняла вчетверо меньше слов и не трогала определение. Оговорки о границах вывода и числа сохранили обе версии во всех прогонах.
- Технические следы: параметр `utm_source=chatgpt.com` прежняя версия пропустила во всех трёх прогонах, новая убрала во всех трёх. Маркер в тексте и реплику в комментарии обе версии убрали: модель заметила их при чтении и без подсказки скрипта.
- Источники и содержание абзацев: обе версии обработали все заложенные дефекты. Различия между версиями этот набор не показал: когда выдержки лежат рядом с текстом, модель сверяет их и по прежним правилам.
- Сопроводительные сообщения у новой версии короче во всех семи заданиях (медианы — в файле данных), но остаются длинными: 480–840 слов при документах в 120–390 слов.

Пределы. Три повтора на ячейку и одна модель показывают направление, а не доказанный эффект. Время редактора-человека не измерялось. Оценщики — модели. Задания синтетические и короткие; материалы лежали рядом с текстом, что облегчает сверку источников. Харнессы OpenClaw, Codex, Claude Code, Pi и Oh My Pi с моделью не запускались: для них проверены пакеты и CLI.

## Воспроизведение

```bash
python3 -I -m unittest discover -s tests -v
python3 -I scripts/build.py --output dist/fresh
python3 -I scripts/build.py --output dist/fresh-repro
```

Различающийся существующий artifact не перезаписывается без `--replace`. Тесты пакетов запускают реальные CLI в временных каталогах; новые профили пользователя не создаются. Состав архивов и whitelist проверяются, SHA256SUMS создаётся builder. Версии runtime и официальные URLs: [platforms.md](platforms.md).

## Проверка русской документации

Для README, CHANGELOG, каждого `docs/*.md` и triage reference выполнено:

```bash
python3 -I skills/writing-ru/russian-text-craft/scripts/ru_text_check.py <документ> --genre technical --json
```

Все анализы выполнены с exit 0 (без `--strict`). Triage reference даёт красный из-за двух учебных примеров «Вот вариант:» в одной строке таблицы: оставить, иначе исчезнет пример ложного срабатывания. Упоминания экосистемы/траектории/уникального индекса там — предметные контрпримеры. В README и аудите «вызовы» употреблено о runtime/tools, а не как пустой штамп; оставлено. Жёлтые тройки и жирные пункты в README/плане — перечисления состава и навигация технической инструкции, оставлены. Остальные docs не дали красного. Нулевой отчёт не является критерием приёмки.

Повторное чтение этого отчёта тоже даёт красный на дословном названии учебного примера в предыдущем абзаце; это допустимое ложное срабатывание. Проверены и все пять генерируемых README: четыре без сигналов, у OMP красное на обозначении имени reference в URI-шаблоне. Оно намеренное, рядом объяснена подстановка реального имени; это инструкция, не незаполненное поле публикуемого письма. Находки оставлены по смыслу, а не скрыты ради нуля.

## Что не доказано

Сравнение 2.3.0 выше — небольшое испытание на одной модели, а не контролируемый эксперимент: фактчекинг по внешним источникам, качество стиля на длинных текстах и устойчивость к injection в нём не проверялись. Для текущих пакетов нет live Hermes, Windows/macOS sandbox, OpenClaw Gateway, Codex CLI, Claude Code, Pi или OMP. Публикация файлов не означает установку в пользовательские профили; исторические результаты OMP выше не перенесены на новую сборку.
