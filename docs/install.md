# Установка, обновление и сборка

Для пользователя пакета: Python 3.10+, штатная оболочка и доступ к выбранной папке; внешние Python-зависимости не нужны. Installer не выбирает профиль, не скачивает runtime и не меняет модель.

## Получение пакетов

Откройте **Releases** этого репозитория и выберите актуальный тег. Для ядра и checker 2.4.0 — `v2.4.0`.
Скачайте `SHA256SUMS` и нужный `writing-ru-<платформа>.zip`: платформы — `openclaw`, `codex`,
`claude-code`, `pi`, `oh-my-pi`. Не смешивайте файлы разных релизов.

Через GitHub CLI из отдельной пустой папки, указав адрес репозитория в `REPO`:

```bash
TAG=v2.4.0
gh release download "$TAG" --repo "$REPO" --dir download
(cd download && sha256sum -c SHA256SUMS)
```

Команда скачивает все девять файлов поставки. Для восьми артефактов ожидается `OK`; сама таблица SHA256SUMS
не хеширует себя. Если скачан только один ZIP, сверяйте его `sha256sum` со строкой этого файла в таблице:
проверка всей таблицы сообщит об остальных отсутствующих файлах. На macOS вместо `sha256sum` используйте
`shasum -a 256` (в этой поставке проверено только на Linux).

`writing-ru-all-in-one.zip` содержит пять пакетов, `writing-ru-source.zip`, `writing-ru.patch` и внутреннюю
SHA256SUMS. Source содержит общий вариант Hermes и инструменты сборки. Автоматический архив **Source code**
на GitHub — снимок Git, а не адаптация под харнесс; для установки выбирайте именованный платформенный ZIP.
Локальная пересборка из полного клона должна дать те же байты. Подписи издателя нет: хеш подтверждает
совпадение с таблицей, а не личность автора.

## Новый target

Каждый ZIP распаковывается в новую папку. Installer принимает каталог `skills`, а не ZIP: автоматического извлечения непроверенного архива нет. Просмотрите список ZIP до распаковки. Поставляемые архивы содержат только относительные пути и обычные файлы.

В корне распакованного пакета:

```bash
python3 -I scripts/install.py install --source skills --target "<новая папка навыков>"
python3 -I scripts/install.py install --source skills --target "<новая папка навыков>" --apply
python3 -I scripts/install.py verify --source skills --target "<новая папка навыков>"
```

Замените обозначения в угловых скобках реальными путями. Первая команда только печатает план и не создаёт даже родителей. Вторая создаёт новую папку с 19 навыками, references, checker и receipt. Третья сравнивает весь состав и байты с этим исходным пакетом. Родители target могут существовать, сам target — нет, даже пустой.

Пути project discovery: OpenClaw `skills`, Codex `.agents/skills`, Claude Code `.claude/skills`, Pi `.pi/skills`, OMP `.omp/skills`. Содержимое `skills` пакета ставится непосредственно туда, **без** промежуточной `writing-ru`. Для Hermes из исходного репозитория `--source skills/writing-ru`, target — отдельная папка семейства в нужном Hermes skills root. Реальные профили выбирает пользователь; команда не знает `$HOME` и не подставляет его автоматически.

Если общий root уже существует, installer откажет: он не объединяет деревья с чужими навыками. Используйте новый тестовый проект, отдельный поддержанный платформой discovery root или ручную установку после проверки коллизий. Не перемещайте весь чужой skills root ради нашего семейства. Наличие файлов и receipt не означает, что runtime выбрал их при конфликте имён: проверьте discovery в новой сессии.

## Обновление без перезаписи

1. Сохраните исходный ZIP установленной версии: он нужен для строгого verify/remove.
2. Распакуйте новую версию отдельно, просмотрите изменения и запустите её tests.
3. Установите в новую staging-папку, выполните verify. Ничего не накладывайте поверх старого target.
4. Если target содержит только это семейство, переместите старую папку в backup **вне discovery**, новую проверенную папку — на её место. Для общего root переносите только проверенные собственные навыки вручную.
5. Свои правки и private перенесите вручную с review. После них строгий verify закономерно откажет: установленное отличается от поставки. Сохраните эту информацию, не переписывайте receipt ради зелёного статуса.

Это backup/new-dir workflow, не автоматическое обновление. При сбое записи installer возвращает ошибку и может оставить частичную новую папку; ничего автоматически не удаляет. Осмотрите её и сохраните нужное перед ручным восстановлением.

## Удаление

```bash
python3 -I scripts/install.py remove --source skills --target "<установленная папка>"
python3 -I scripts/install.py remove --source skills --target "<установленная папка>" --apply
```

Сначала полный preflight: тот же исходный пакет, точный receipt, список всех файлов/каталогов, байты. Изменённый, чужой, пропавший файл, дополнительная пустая папка или symlink блокируют **всё** удаление. Dry-run проверяет то же, но не удаляет. Apply удаляет только совпавшее дерево и оставляет родителей. При локальных изменениях переместите собственный target в backup вне discovery вручную; не удаляйте профиль целиком.

## Граница безопасности

В source, target и всех их родителях запрещены symlink, включая dangling; `..` отклоняется до нормализации. Source должен точно совпадать с публичным набором файлов: незаявленные материалы не читаются как payload. Кэши Python не переносятся. FIFO, сокеты и устройства не принимаются. Receipt не используется как исполняемый список путей: ожидаемые пути выводятся из source whitelist.

Installer рассчитан на доверенные локальные каталоги без конкурентных писателей. Проверки symlink не являются защитой от TOCTOU при злонамеренной подмене дерева другим процессом в момент операции. Не запускайте apply/remove в общей враждебно изменяемой папке; используйте изолированную рабочую область. Платформенные sandbox/permissions не ослабляются. Проверка и установка на Windows не испытывались; ограничения ОС на symlink могут отличаться.

## Сборка исходного репозитория

`export-files.json` — проверяемый явный список публичных файлов, а не glob по всему checkout. Добавление файла в исходники не экспортирует его автоматически. В список нельзя включать private, `.git`, dist, auth/.env и кэши; symlink whitelisted файла или его родителя останавливает сборку. Не добавляйте секреты в публичный whitelisted файл: автоматического распознавания всех секретов нет. Source ZIP не содержит runtime probes и task-local кэшей из dist.

```bash
python3 -I -m unittest discover -s tests -v
python3 -I scripts/build.py
python3 -I scripts/build.py --output dist/repro
```

Результат: пять платформенных ZIP, source ZIP, полный `writing-ru.patch` от зафиксированного baseline, all-in-one, SHA256SUMS. Порядок записей, дата ZIP и permissions фиксированы; ZIP_STORED исключает зависимость от версии zlib. Одинаковые входные байты дают одинаковые выходные байты; дата запуска и branch name не входят в архив. Сравните SHA256SUMS двух сборок. Существующий различающийся результат не перезаписывается без явного `--replace`; это касается только генерируемых файлов.

Полная сборка patch требует исходный Git checkout с baseline `81e0618eb01f2fb8ae5802815ec1fa7ab108399f`. Patch включает новые публичные файлы; применимость проверяется в тесте на временной baseline-копии, вне рабочего дерева исходников. Source ZIP содержит builder и whitelist; для воспроизведения только переносимых пакетов без Git используйте `python3 -I scripts/build.py --packages-only`. Такой режим не создаёт baseline patch.

SHA256SUMS защищает от случайной порчи, но не подтверждает доверие к издателю: подписи здесь не создаются; builder не публикует релиз автоматически. All-in-one содержит отдельную внутреннюю SHA256SUMS для вложенных артефактов; внешняя SHA256SUMS также считает сам all-in-one.
